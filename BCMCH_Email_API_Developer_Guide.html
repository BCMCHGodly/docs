01 / API overview

Use the BCMCH Notification System to submit email notification requests to one or more recipients with a subject and HTML message body.

POST{{BaseUrl}}/api/notifications

Request format: JSON. Channel: Email.

02 / Configuration and authentication

VariableDescription
BaseUrlBCMCH-provided base URL for the target environment.
TokenBCMCH-provided authorization header value. Use the exact format issued by the integration team.

HTTP headers

Content-Type: application/json
Authorization: {{Token}}

Configure the variables in Postman or replace them with the appropriate values in your application. Do not expose credentials in source code or client-side applications.

03 / Request payload

FieldTypeDescription
channelStringUse Email for email notifications.
requestIdStringClient-generated request identifier for correlation. Generate a unique value for each new logical request.
recipientsArray of stringsEmail addresses of intended recipients.
contentObjectEmail content container.
content.subjectStringEmail subject line.
content.htmlBodyStringEmail message body, including optional HTML markup.

Include all fields shown in the supplied request. Server-side validation rules and field limits have not been confirmed.

04 / Integration examples

cURL request

curl --location '{{BaseUrl}}/api/notifications' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: {{Token}}' \
  --data-raw '{
    "channel": "Email",
    "requestId": "key-1795605995-0ee159d8-79db-4536-adcd-2e102183e27d",
    "recipients": [
      "godly@bcmch.org",
      "sai.ganesh@analystortech.com"
    ],
    "content": {
      "subject": "Test Subject",
      "htmlBody": "Hello there....!"
    }
  }'

Postman / dynamic request body

Select POST, configure the headers, and choose Body → raw → JSON.

{
  "channel": "Email",
  "requestId": "key-{{$timestamp}}-{{$randomUUID}}",
  "recipients": [
    "godly@bcmch.org",
    "sai.ganesh@analystortech.com"
  ],
  "content": {
    "subject": "Test Subject",
    "htmlBody": "Hello there....!"
  }
}

Postman resolves {{$timestamp}} to a Unix timestamp in seconds and {{$randomUUID}} to a generated UUID. Outside Postman, generate equivalent values in application code. The literal placeholders are not intended for transmission.

HTML message body example

"content": {
  "subject": "Test Subject",
  "htmlBody": "<div style=\"font-family:Arial,sans-serif;\">Hello there....!</div>"
}

Use a JSON serializer to escape HTML content correctly.

05 / API response

Response contract pending confirmation. The supplied response example repeats the request payload and contains Postman dynamic variables. It is documented above as a request template, not as a verified server response.

Capture the actual HTTP status and response body during integration testing. Confirm the success response schema, error schema, notification identifier (if returned), and delivery status semantics with the BCMCH integration team. A successful HTTP response alone does not establish email delivery.

06 / Integration guidelines

  • Use HTTPS and store authorization credentials securely on the server.
  • Validate recipient addresses and message content before submitting requests.
  • Generate a unique request ID for each new logical notification and retain it for troubleshooting.
  • Confirm retry and idempotency behavior before enabling automatic retries to avoid duplicate emails.
  • Record HTTP status, request ID and sanitized error information. Avoid logging tokens or sensitive email content.
  • Use authorized test recipients in UAT. Confirm environment restrictions before sending.
  • Confirm recipient limits, payload size limits, rate limits and delivery tracking capabilities before production rollout.
